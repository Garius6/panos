# Сеть и HTTP

> Требует `импорт сеть` и реальную сеть — **недоступно** в браузерной
> песочнице (см. [«Модули» → ограничение в браузере](./modules.md#ограничение-в-браузере)).
> Примеры не запускаются на странице, запускайте локально: `./panos файл.pns`.

## `сеть`: TCP-клиент

```panos-cli
импорт сеть

функ старт() -> Строка
    пер соединение = сеть.подключиться("example.com", 80).ожидать("не удалось подключиться")
    соединение.отправить("GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n")
    пер ответ = соединение.получить().получить("(пусто)")
    соединение.закрыть()
    ответ
конец
```

- `сеть.подключиться(хост, порт) -> Результат(Соединение, Ошибка)` — TCP,
  без TLS (`https://` не поддержан, см. ниже)
- `.отправить(текст) -> Результат(Число, Ошибка)`
- `.получить() -> Результат(Строка, Ошибка)` — читает до закрытия
  соединения удалённой стороной (до EOF)
- `.получить_строку() -> Результат(Строка, Ошибка)` — одна строка
- `.закрыть() -> Пусто`
- `сеть.кодировать_url(текст) -> Строка` — percent-encoding
  (`сеть.кодировать_url("а б")` → `"%D0%B0%20%D0%B1"`)

## `сеть/http`: HTTP(S)-клиент

Тонкая обёртка (`std/сеть/http.pns`) над builtin `сеть.http_запрос` —
настоящий HTTP-клиент (`std.http.Client` из стандартной библиотеки Zig,
см. `zig/core/vm.zig`), а не ручной сокет-парсер. Импортируется
по пути в кавычках, потому что имя содержит `/`:

```panos-cli
импорт "сеть/http" как http
импорт строки

функ старт() -> Строка
    пер ответ = http.запросить("https://example.com/").ожидать("запрос не удался")
    если ответ.успех() тогда
        ответ.тело
    иначе
        "код ответа: " + строки.из_целого(ответ.статус)
    конец
конец
```

И `http://`, и `https://`. Корректно обрабатывает `Content-Length` и
`Transfer-Encoding: chunked` (в отличие от старой реализации — та читала
тело до закрытия соединения, что портило chunked-ответы). Заголовки
ответа приходят в нижнем регистре (так их хранит native-клиент) —
`.заголовок(имя)` ищет без учёта регистра, прямой доступ через
`.заголовки.получить(...)` — с учётом.

Единственная системная зависимость во всём проекте (не вендорится, в
отличие от libffi) — на macOS/Linux нужен установленный OpenSSL 3.x
(`brew install openssl@3` / `apt install libssl-dev`) для сборки самого
`panos`; на Windows статические `.lib` уже в репозитории. Недоступно в
WASM-демо (тот же принцип, что `фс`/`сеть` — см. выше).

**Функции:**

- `http.запросить(ссылка) -> Результат(Ответ, Ошибка)` — GET
- `http.получить_с_заголовками(ссылка, заголовки) -> Результат(Ответ, Ошибка)`
- `http.запросить_head(ссылка) -> Результат(Ответ, Ошибка)` — HEAD
- `http.отправить_пост(ссылка, тело)` / `.отправить_put(ссылка, тело)` /
  `.отправить_patch(ссылка, тело) -> Результат(Ответ, Ошибка)` — и
  `_с_заголовками`-варианты каждого (доп. `Соответствие(Строка, Строка)`
  последним аргументом)
- `http.удалить(ссылка)` / `.удалить_с_заголовками(ссылка, заголовки) -> Результат(Ответ, Ошибка)` — DELETE
- `http.отправить_json(ссылка, значение: json.Значение) -> Результат(Ответ, Ошибка)`
  — сериализует через `кодирование/json`, ставит
  `Content-Type: application/json`
- `http.запросить_с_редиректами(ссылка, макс_переходов) -> Результат(Ответ, Ошибка)`
  — следует за `3xx`/`Location` (абсолютным и относительным), падает
  `Ошибка`, если лимит превышен
- `http.построить_query(параметры) -> Строка` — собирает
  `?ключ=значение&...` из `Соответствие(Строка, Строка)`, значения уже
  percent-encoded
- `http.разобрать_адрес(текст) -> Результат(Адрес, Ошибка)` — оставлено
  для обратной совместимости (только `http://`); сам `http_запрос` URL
  парсит внутри native-клиента, эта функция для запросов не нужна

**Тип `Ответ`:**

```panos
тип Ответ = структура
    статус:    Число
    заголовки: Соответствие(Строка, Строка)
    тело:      Строка
конец
```

Методы: `.успех()` (2xx), `.редирект()` (3xx), `.ошибка_клиента()` (4xx),
`.ошибка_сервера()` (5xx), `.заголовок(имя) -> Опция(Строка)` (без учёта
регистра).

## `сеть`: HTTP-сервер

Builtin `сеть.http_сервер_слушать`/`.принять_запрос()`/`.ответить(...)` —
низкоуровневый accept-loop поверх `std.http.Server` из стандартной
библиотеки Zig (не отдельный сокет-парсер).

```panos-cli
импорт сеть

функ старт() -> Пусто
    пер слушатель = сеть.http_сервер_слушать(8080).ожидать("не смог слушать")
    пока истина цикл
        пер запрос_рез = слушатель.принять_запрос()
        если запрос_рез.ошибка() тогда
            продолжить
        конец
        пер запрос = запрос_рез.значение()
        запрос.ответить(200, "text/plain", "привет: " + запрос.путь())
    конец
конец
```

- `сеть.http_сервер_слушать(порт) -> Результат(Слушатель, Ошибка)` —
  биндит порт один раз; повторный биндинг того же порта — `Неудача`
- `Слушатель.принять_запрос() -> Результат(Запрос, Ошибка)` — асинхронно
  ждёт следующий запрос (тот же worker-пул, что у остального async I/O);
  можно звать из НЕСКОЛЬКИХ процессов на ОДНОМ слушателе — каждый запрос
  достаётся ровно одному
- `Запрос.метод()` / `.путь()` / `.заголовки()` / `.тело() -> Строка`
- `Запрос.ответить(статус: Целое, тип_содержимого: Строка, тело: Строка) -> Результат(Пусто, Ошибка)`
  — `Неудача`, если клиент уже отвалился ИЛИ на этот запрос уже отвечали
  раньше (повторный `.ответить()` — не паника)
- `Запрос.ответить_с_заголовками(статус, тип_содержимого, тело, заголовки: Соответствие(Строка, Строка)) -> Пусто`
  — то же самое плюс произвольные дополнительные заголовки (`Location`
  для редиректов, `Set-Cookie` для сессий и т.п.)

`сеть/http` добавляет сахарную обёртку — обработчик как обычная функция
`Запрос -> ОтветСервера`, без ручного `ответить(...)`/развёртывания
`Результат` на каждой итерации:

```panos-cli
импорт "сеть/http" как http

функ обработчик(запрос: Запрос) -> http.ОтветСервера
    http.ответ(200, "text/plain", "привет: " + запрос.путь())
конец

функ старт() -> Результат(Число, Ошибка)
    http.обслуживать(8080, обработчик, 4)
конец
```

- `http.ОтветСервера{статус, тип_содержимого, тело, заголовки}` — то, что
  возвращает обработчик
- `http.ответ(статус, тип_содержимого, тело) -> ОтветСервера` — сокращение
  без дополнительных заголовков (самый частый случай)
- `http.ответ_редирект(путь) -> ОтветСервера` — `302` с `Location: путь`
- `http.Обработчик = функ(Запрос) -> ОтветСервера`
- `http.обслуживать_слушатель(слушатель, обработчик) -> Пусто` —
  accept-цикл над уже открытым `Слушателем`, никогда не возвращается;
  несколько процессов могут звать это над ОДНИМ слушателем
- `http.обслуживать(порт, обработчик, процессов) -> Результат(Число, Ошибка)`
  — биндит порт и сам спавнит `процессов - 1` дополнительных обработчиков
  через `запусти` (плюс вызывающий процесс — итого `процессов`); при
  успехе не возвращается, `Результат` только для ошибки биндинга.
  `процессов` — НЕ параллелизм (VM однопоточная, кооперативная), а
  конкурентность: пока один обработчик ждёт свой I/O, другие продолжают
  принимать запросы вместо простоя за ним; реальный потолок — 4 (единый
  на весь VM пул воркеров async I/O)

Недоступно в WASM-демо (то же ограничение, что у клиента/`фс` выше).

## `сеть/http`: Роутер

`Маршрутизатор` — диспетчеризация по (метод, путь) поверх `обслуживать`,
без изменений самого accept-loop.

```panos-cli
импорт "сеть/http" как http

функ показать_пользователя(зм: http.ЗапросМаршрута) -> http.ОтветСервера
    пер id = зм.параметры.получить("id", "")
    http.ответ(200, "text/plain", "пользователь " + id)
конец

функ старт() -> Результат(Число, Ошибка)
    пер р = http.маршрутизатор()
    р.получить("/пользователи/:id", показать_пользователя)
    http.обслуживать(8080, р.как_обработчик(), 4)
конец
```

- `http.маршрутизатор() -> Маршрутизатор`
- `.получить` / `.отправить_пост` / `.отправить_put` / `.отправить_patch`
  / `.удалить(шаблон: Строка, обработчик: ОбработчикМаршрута) -> Пусто`
  — регистрирует обработчик на метод+шаблон пути (`:имя` — именованный
  параметр сегмента, wildcard'ов нет)
- `http.ОбработчикМаршрута = функ(ЗапросМаршрута) -> ОтветСервера`
- `http.ЗапросМаршрута{запрос: Запрос, параметры: Соответствие(Строка, Строка)}`
  — `Запрос` нативный opaque-тип, поэтому роутер оборачивает его вместо
  того, чтобы дописывать поле параметров в сам `Запрос`
- `.как_обработчик() -> Обработчик` — передать в `обслуживать`/
  `обслуживать_слушатель`; порядок регистрации маршрутов относительно
  этого вызова не важен (Маршрутизатор — ссылочный тип, `.получить(...)`
  после `.как_обработчик()` тоже сработает, просто регистрация-потом-
  обслуживание — более понятный стиль)
- Несовпавший путь/метод → встроенный `404`
- `http.сопоставить_путь(шаблон, путь) -> Опция(Соответствие(Строка, Строка))`
  / `http.скомпилировать_путь(шаблон) -> Шаблон_Пути` — тот же матчер
  отдельно от роутера, для ручной диспетчеризации через `выбор` вместо
  `Маршрутизатор`

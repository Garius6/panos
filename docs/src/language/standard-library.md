# Стандартная библиотека

Модули из `std/` (репозиторий: `std/математика.pns`, `std/коллекции.pns` и
т.д.) — написаны на самом panos, а не встроены в компилятор. Резолвятся
как обычный `импорт` (см. [«Модули»](./modules.md)) через `PANOS_STDLIB`/
`модули/`/репозиторный `std/`. HTTP-клиент/сервер/роутер (`сеть/http`)
вынесены в [«Сеть и HTTP»](./networking.md) — используют `сеть`, поэтому
недоступны в браузере; всё остальное на этой странице — чистые вычисления,
работает и в интерактивной песочнице.

## `математика`

```panos
импорт математика

функ старт() -> Число
    математика.степень(2.0, 10.0) + математика.квадратный_корень(16.0)
конец
```

`пи()`, `е()`, `квадрат(x)`, `абс(x)`, `мин(a, b)`, `макс(a, b)`,
`степень(x, n)` (целая степень, `n` может быть отрицательным),
`квадратный_корень(x)` (метод Ньютона, `x <= 0` даёт `0` — без `Опция`/
паники).

`округл_вниз(x)`/`округл_вверх(x)`/`округлить(x)` — округление к целому
значению, результат — `Число` (не `Целое`: коэрсии между ними всё ещё нет,
см. [«Число и Целое»](./basic-types.md#число-и-целое), но она и не нужна
для округления — усечение реализовано бинарным спуском по степеням
двойки, целиком в `Число`). `округлить` — половина округляется от нуля
(`округлить(2.5) == 3`, `округлить(-2.5) == -3`).

`синус(x)`/`косинус(x)`/`тангенс(x)` (радианы), `экспонента(x)` (e^x),
`логарифм(x)` (натуральный, `x <= 0` даёт `0`), `атан(x)`/`асин(x)`/
`акос(x)`, `атан2(y, x)` (полный диапазон, все 4 квадранта) — все чистый
panos (ряды Тейлора/Маклорена с редукцией аргумента), без FFI, поэтому
работают и в WASM AOT. Точность — около `1e-6`, этого достаточно для
игровой/скриптовой математики, но не для научных вычислений:

```panos
импорт математика

функ старт() -> Число
    математика.синус(математика.пи() / 2.0) + математика.атан2(1.0, 1.0)
конец
```

Генератор случайных чисел — `следующее(seed)`/`дробь(seed)`/
`диапазон(seed, нижняя, верхняя)` (Lehmer/Park-Miller LCG). `seed` явный:
в panos нет модульных глобальных переменных, поэтому состояние генератора
пробрасывается вызывающим кодом между вызовами, а не хранится неявно
внутри модуля; `seed` должен быть ненулевым. Первый seed обычно берут из
`время.монотонно_мс()`:

```panos
импорт математика
импорт время

функ старт() -> Число
    пер seed = время.монотонно_мс()
    математика.диапазон(seed, 1.0, 6.0)  // кубик 1..6
конец
```

Построение строк из значений — интерполяция `\(x)` прямо в литерале (см.
[«Строки» → «Интерполяция»](./basic-types.md#интерполяция)), не отдельный
stdlib-модуль.

## `коллекции`

Generic-комбинаторы над `Массив(T)` — компараторы передаются лямбдой, не
встроенным `<`, поэтому `отсортировать` работает и на типах без
`реализация Сравниваемое`:

```panos
импорт коллекции

функ старт() -> Целое
    пер числа = массив(3, 1, 4, 1, 5)
    пер отсортированные = коллекции.отсортировать(числа, функ(a, b) a < b конец)
    пер сумма = коллекции.свернуть(числа, 0, функ(накопитель, x) накопитель + x конец)
    отсортированные[0] + сумма
конец
```

- `отфильтровать[T](массив, предикат: функ(T) -> Булево) -> Массив(T)`
- `отобразить[T, U](массив, преобразование: функ(T) -> U) -> Массив(U)`
- `свернуть[T, U](массив, начало: U, шаг: функ(U, T) -> U) -> U`
- `отсортировать[T](массив, меньше: функ(T, T) -> Булево) -> Массив(T)` —
  insertion sort, стабильная
- `найти[T](массив, предикат) -> Опция(T)` / `индекс_где[T](массив, предикат) -> Опция(Целое)`
- `любой[T](массив, предикат) -> Булево` / `все[T](массив, предикат) -> Булево`
- `уникальные[T](массив) -> Массив(T)` — без предикатов сравнения, через
  структурное равенство (нативный `.содержит()`, работает для любого `T`)
- `развернуть[T](массив) -> Массив(T)`
- `сгруппировать[T](массив, ключ: функ(T) -> Строка) -> Соответствие(Строка, Массив(T))`
- `zip[T, U](а, б) -> Массив((T, U))` — до длины короче из двух
- `фрагменты[T](массив, размер: Целое) -> Массив(Массив(T))`

`Массив` уже имеет нативный метод `.содержит(x)` — не дублируется
функцией `коллекции`.

## `путь`: манипуляция путями

Чистая строковая логика, без обращения к файловой системе (это не
`фс`) — POSIX-стиль (`/`), Windows-путь (`C:\`) не распознаётся:

```panos
импорт путь

функ старт() -> Строка
    путь.соединить(путь.директория("проект/src/main.ps"), "utils.ps")
конец
```

- `соединить(а, б) -> Строка` / `соединить_все(сегменты: Массив(Строка)) -> Строка`
- `имя_файла(путь) -> Строка` / `директория(путь) -> Строка`
- `расширение(путь) -> Опция(Строка)` (без точки; скрытые файлы вроде
  `.gitignore` — без расширения) / `без_расширения(путь) -> Строка`
- `абсолютный(путь) -> Булево`

## `флаги`: разбор аргументов командной строки

```panos
импорт флаги

функ старт() -> Строка
    пер конфиг = флаги.новая_конфигурация()
    конфиг.добавить_флаг(флаги.Флаг("имя", флаги.ТипФлага.тСтрока))
    пер результат = конфиг.распарсить_флаги(массив("-имя=мир"))
    результат.получить("имя", флаги.ЗначениеФлага.фСтрока("")).вСтроку()
конец
```

Объявите флаги через `Флаг(наименование, тип)` (`ТипФлага.тСтрока` /
`.тЧисло` / `.тБулево`), добавьте их в `Конфигурация` через
`.добавить_флаг`, затем разберите либо явный массив строк
(`.распарсить_флаги(аргументы)` — как выше, удобно для тестов), либо
сразу `ос.аргументы()` через `.распарсить()` (требует `импорт ос`, см.
[«Использование CLI»](../getting-started/cli.md)). Поддержаны формы
`-флаг=значение` и `-флаг значение`; для `тБулево` значение не читается —
само присутствие флага значит `истина`. Необъявленный флаг или
пропущенное значение — паника, не `Результат` (тот же принцип, что у
`кодирование/json`/`кодирование/toml` ниже: ошибка во входных данных —
критичный сбой).

## `кодирование/json`, `кодирование/toml`

Оба модуля — парсеры в дерево `Значение` с одинаковым интерфейсом доступа
и оба умеют сериализовать обратно в текст. Импортируются по пути в
кавычках (имя с `/`):

```panos
импорт "кодирование/json" как json

функ старт() -> Строка
    пер результат = json.разобрать("{\"имя\": \"panos\", \"версия\": 1}")
    если результат.ошибка() тогда
        возврат "ошибка парсинга"
    конец
    результат.значение().поле("имя").значение().как_строку().получить("?")
конец
```

`разобрать(текст) -> Результат(Значение, Ошибка)` и
`сериализовать(значение) -> Строка` — есть в обоих модулях.

Методы `Значение` — общие для обоих модулей:

- `.как_строку() / .как_число() / .как_булево() -> Опция(...)`
- `.поле(ключ) -> Опция(Значение)` — для объекта (JSON) / таблицы (TOML)
- `.элемент(индекс) -> Опция(Значение)` — для списка

`json.разобрать` корректно декодирует `\uXXXX`-escape'ы в строках,
включая суррогатные пары (codepoint'ы за пределами BMP — эмодзи и
т.п., кодируются JSON как ДВА `\u` подряд). `json.сериализовать`
экранирует управляющие байты < 0x20 через `\u00XX` — валидный JSON на
выходе для любого текста, не только "типичного".

`json.объект(поля: Массив((Строка, Значение))) -> Значение` /
`json.список(элементы: Массив(Значение)) -> Значение` — builder-хелперы
для ручной сборки дерева `Значение` (без прямого обращения к
`Значение.Объект(соответствие(...))`):

```panos
импорт "кодирование/json" как json

функ старт() -> Строка
    пер значение = json.объект(массив(
        ("имя", json.Значение.Строка("panos")),
        ("теги", json.список(массив(json.Значение.Строка("panos"), json.Значение.Строка("panosiki"))))
    ))
    json.сериализовать(значение)
конец
```

Варианты `Значение` отражают форму каждого формата. JSON:
`Ноль`/`Булево(Булево)`/`Число(Число)`/`Строка(Строка)`/
`Список(Массив(Значение))`/`Объект(Соответствие(Строка, Значение))`.

TOML отдельно различает целые и дробные числа (как и сам язык panos —
`Целое`/`Число`), и добавляет дата-время как сырой текст (структурного
типа даты в языке нет):
`Строка(Строка)`/`Целое(Целое)`/`Число(Число)`/`Булево(Булево)`/
`Время(Строка)`/`Список(Массив(Значение))`/
`Таблица(Соответствие(Строка, Значение))`. Доп. методы:
`.как_целое() -> Опция(Целое)`, `.как_время() -> Опция(Строка)`;
`.как_число()` работает и для `Целое`, и для `Число` (расширяет целое
до дробного).

`кодирование/toml` — hand-written реализация TOML v1.0.0 на чистом
panos (без внешних/нативных TOML-библиотек): базовые/литеральные строки
(в т.ч. многострочные `"""···"""`/`'''···'''` с полным набором
escape-последовательностей, включая `\uXXXX`/`\UXXXXXXXX`), целые
(десятичные со знаком, `0x`/`0o`/`0b` без знака, `_`-разделители),
дробные (экспонента, `inf`/`nan` и их `±`-варианты), точечные ключи
(`a.b.c = 1`), вложенные секции (`[a.b.c]`), массивы таблиц (`[[a.b]]`),
инлайн-таблицы (`{ x = 1, y = 2 }`), многострочные массивы, кавычечные
ключи. Сознательно не поддержано (нишевые случаи, не стоящие объёма для
hand-written парсера): дата-время с пробелом вместо `T` между датой и
временем (читается как два отдельных токена — используйте `T`),
bare-ключи, начинающиеся с цифры.

## `тест`: минимальный ассерт-фреймворк

```panos
импорт тест
импорт математика

функ старт() -> Пусто
    пер отчёт = тест.новый_отчёт()
    тест.проверить(отчёт, 2 + 2 == 4, "арифметика сломана")
    тест.равны(отчёт, математика.степень(2.0, 3.0), 8.0, "степень считает неверно")
    тест.напечатать_сводку(отчёт)
    если отчёт.провалено > 0 тогда
        паника("тесты провалены")
    конец
конец
```

`Отчёт` копит пройдено/провалено вместо паники на первом же провале —
`проверить(отчёт, условие, сообщение)` и generic `равны[T]`/`не_равны[T]
(отчёт, a, b, сообщение)` продолжают прогон, `напечатать_сводку(отчёт)`
печатает итог + список провалившихся сообщений. Панику (если она вообще
нужна) вызывающий код добавляет сам — так CI видит полную сводку, а не
только первый провал.

`ожидать_панику(отчёт, причина, сообщение)` — assert "код должен был
запаниковать": в panos нет try/catch, единственный способ поймать панику
— посадить проверяемый код в отдельный процесс (`запусти`) и получить
причину краша через `наблюдать`/`получить_сигнал` (см.
[«Процессы»](./processes.md)):

```panos
импорт тест

функ падающая_операция() -> Пусто
    паника("что-то пошло не так")
конец

функ старт() -> Пусто
    пер отчёт = тест.новый_отчёт()
    пер процесс = запусти падающая_операция()
    наблюдать(процесс)
    пер (_, причина) = получить_сигнал()
    тест.ожидать_панику(отчёт, причина, "падающая_операция должна паниковать")
    тест.напечатать_сводку(отчёт)
конец
```

## `сжатие`

Тонкая обёртка над `std.compress.flate` (Zig) — DEFLATE/Хаффман не
реализуем в чистом panos (нет битовых операторов, `Массив(T)` — не
байтовый буфер, см. обсуждение архитектуры), поэтому распаковка — core
builtin, а не stdlib-модуль:

```panos
импорт сжатие
импорт фс

функ старт() -> Строка
    выбор фс.прочитать("архив.tar.gz")
        Результат.Успех(данные) ->
            выбор сжатие.разжать_gzip(данные)
                Результат.Успех(текст) -> текст
                Результат.Неудача(ош) -> "ошибка распаковки"
            конец
        Результат.Неудача(ош) -> "не удалось прочитать файл"
    конец
конец
```

`разжать_gzip(данные) -> Результат(Строка, Ошибка)`. Только распаковка —
записи (сжатие на запись) core:compress не поддерживает. В нативной VM
распаковка выполняется в фоновом потоке: ожидает только вызвавший
процесс, а другие акторы продолжают работу. Недоступно в browser/WASM-
таргетах.

## `архив`: tar

Чистый panos (парсинг/сборка ustar-заголовков) поверх `строки.в_байты`/
`из_байтов` и обычных методов `Массив(Целое)` (см.
[«Строки» → «Байты»](./basic-types.md#байты)) — тот же принцип, что
`кодирование/json`/`кодирование/toml`: сам формат на panos, только
низкоуровневый доступ к байтам — core builtin.

```panos
импорт архив
импорт фс

функ старт() -> Пусто
    пер записи: Массив(архив.Запись) = массив(
        архив.Запись("привет.txt", "Привет, мир!", ложь)
    )
    фс.записать(".zig-cache/вывод.tar", архив.собрать(записи))
конец
```

`Запись { имя: Строка, содержимое: Строка, каталог: Булево }`.
`разобрать(данные) -> Массив(Запись)`, `собрать(записи) -> Строка` —
обычные файлы/каталоги, ustar-подмножество полей (без symlink/hardlink/
устройств, GNU длинных имён, PAX-заголовков — такие записи парсятся как
обычные "файлы" с их сырым содержимым, не как метаданные). Проверено на
кросс-совместимость с настоящим `tar` (GNU и BSD, включая архивы с
AppleDouble/PAX-записями от macOS) в обе стороны.

`разобрать_tar_gz(данные) -> Результат(Массив(Запись), Ошибка)` —
удобство: `сжатие.разжать_gzip` + `разобрать` одним вызовом для `.tar.gz`.

## `дата`: форматирование дат

```panos
импорт дата
импорт время

функ старт() -> Строка
    дата.форматировать_utc(время.сейчас_мс())
конец
```

`форматировать_utc(epoch_мс: Число) -> Строка` — `"ГГГГ-ММ-ДД ЧЧ:ММ:СС"`,
всегда UTC (без часовых поясов). Только для НЕОТРИЦАТЕЛЬНЫХ `epoch_мс`
(1970-01-01 и позже) — реализует civil-calendar алгоритм Говарда Хайнанта
([date_algorithms](http://howardhinnant.github.io/date_algorithms.html))
без ветки для отрицательных `z` (дат до эпохи): единственный сценарий,
под который это писалось — форматирование `время.сейчас_мс()`, тащить
неиспользуемую отрицательную ветку — необязательный риск тихой ошибки в
date-математике. Использует `математика.округл_вниз` для деления вместо
битовых операций (в panos их нет) — проверено вручную против `date -u`
на нескольких границах, включая конец/начало года и 29 февраля
високосного года.

## `слог`: логирование

```panos
импорт слог

функ старт() -> Пусто
    слог.инфо("сервер запущен")
    слог.предупреждение("свободное место на диске мало")
    слог.ошибка("не удалось подключиться к БД")
конец
```

`отладка(текст)` / `инфо(текст)` / `предупреждение(текст)` /
`ошибка(текст)` / `критично(текст) -> Пусто` — каждая печатает текст с
префиксом уровня (`[ИНФО]`, `[ОШИБКА]` и т.д.) через `ввод_вывод.строка`,
безусловно (без фильтрации/тегов) — простой случай, требует ровно
`импорт слог` и ничего больше.

### `Логгер`: фильтрация, теги, несколько приёмников, структурные поля

`Логгер` — ИНТЕРФЕЙС (пять методов: `отладка`/`инфо`/`предупреждение`/
`ошибка`/`критично`), не конкретный тип: код, которому нужно просто
логировать (не строить/настраивать логгер), пишет `функ f(л: слог.
Логгер)` и получает ЛЮБУЮ реализацию — встроенную `СтандартныйЛоггер`
ниже, тестовый no-op-логгер, логгер, отправляющий записи во внешнюю
систему напрямую. Реализуйте `реализация слог.Логгер для ВашТип` с этими
пятью методами и подставляйте вместо `СтандартныйЛоггер` где угодно.

`СтандартныйЛоггер` — встроенная реализация: явный объект вместо неявной
глобальной настройки — panos не хранит модульных глобальных переменных
(`конст` — compile-time подстановка, не рантайм-ячейка), к тому же
`запусти` кооперативно шарит один VM/heap между процессами: скрытая
глобальная настройка была бы неохраняемым бэкдором общей памяти в обход
message-passing изоляции actor-модели. Тот же паттерн явного состояния,
что у `математика.Генератор`.

```panos-cli
импорт слог

функ старт() -> Пусто
    пер л = слог.логгер().с_уровнем(слог.Уровень.Инфо).с_тегом("http")
    л.отладка("не напечатается — ниже порога")
    л.инфо("сервер запущен")
    л.запись_с_полями(слог.Уровень.Сбой, "запрос упал", соответствие(
        "путь" = "/x",
        "статус" = "500",
    ))
конец
```

- `слог.логгер() -> СтандартныйЛоггер` — по умолчанию: печатает всё
  (`Отладка` и выше) в консоль, без тега. Возвращает КОНКРЕТНЫЙ тип, не
  интерфейс `Логгер` — цепочка `.с_уровнем(...).с_тегом(...)` работает
  только на конкретном типе (интерфейсное значение видит только пять
  объявленных методов Логгер, билдер-методы туда не входят); приводится
  к `Логгер` автоматически там, где ожидается этот тип (параметр функции
  и т.п.)
- `.с_уровнем(минимальный: Уровень) -> СтандартныйЛоггер` — записи ниже
  этого уровня становятся no-op; `Уровень` — `Отладка`/`Инфо`/
  `Предупреждение`/`Сбой`/`Критично` (не `Ошибка` — конфликтует с
  встроенным типом `Ошибка`, но печатается как `[ОШИБКА]`, как и раньше)
- `.с_тегом(тег: Строка) -> СтандартныйЛоггер` — добавляет `[тег]` в
  каждую строку; повторный вызов заменяет тег, не вкладывает
- `.с_приёмником(приёмник: Приёмник) -> СтандартныйЛоггер` — ДОБАВЛЯЕТ
  приёмник (пишет во все сразу), не заменяет
- `.отладка(текст)` / `.инфо(текст)` / `.предупреждение(текст)` /
  `.ошибка(текст)` / `.критично(текст) -> Пусто` — методы интерфейса
  `Логгер`, временная метка через `дата.форматировать_utc`
- `.запись_с_полями(уровень: Уровень, текст: Строка, поля: Соответствие(Строка, Строка)) -> Пусто`
  — структурные поля, сериализуются как `ключ=значение` через пробел
  после текста (НЕ часть интерфейса `Логгер` — только на конкретном
  `СтандартныйЛоггер`)

**Приёмники** (`Приёмник = функ(Строка) -> Пусто`, обычная
функция-значение — можно передать свою, не только встроенные):

- `слог.приёмник_консоль() -> Приёмник` — stdout (это то, что даёт
  `логгер()` по умолчанию)
- `слог.приёмник_файл(путь) -> Результат(Приёмник, Ошибка)` — открывает
  файл ОДИН РАЗ при создании и держит открытым на весь срок жизни
  приёмника; недоступно в браузере (как и весь `фс`)

Замена `logos` (oscript-library) под порт gitsync — не полный аналог
(нет layout'ов/ротации файлов), но перекрывает типичный случай
(уровень/тег/несколько приёмников/структурные данные), которого не было
у изначальной пятифункциональной версии.

# Contract: публичный `panos_embed`-API после этой фичи

Дополняет (не заменяет) существующий контракт `docs/src/architecture/
embedding.md`. Обратная совместимость — обязательна (FR-007): всё, что
описано в `embedding.md` сегодня, продолжает работать буквально без
изменений.

## Новый публичный символ: `panos.hostFunctions`

```zig
pub fn hostFunctions(comptime table: anytype) []const HostFunctionEntry
```

- **Вход**: анонимный `struct`-литерал, поля — обычные Zig-функции.
  Каждое имя поля становится именем, доступным `.pns`-стороне через
  `внешний "хост" функ <имя_поля>(...)`.
- **Compile-time контракт**: если тип параметра или возврата любой функции
  в `table` не отображается на существующий набор `ForeignMarshalKind`
  (`Целое(8|32|64)`/`Число(32|64)`/`КСтрока`/`ff_структура`/`Указатель(T)`
  — см. `data-model.md`, "Соответствие типов") — `@compileError` В МЕСТЕ
  ВЫЗОВА `hostFunctions(...)`, сборка движка не проходит. Это часть
  контракта, не деталь реализации: игровой код узнаёт о несовместимой
  сигнатуре на `zig build`, не при запуске уровня.
- **Выход**: `[]const HostFunctionEntry` — непрозрачный для
  вызывающего кода тип, передаётся ТОЛЬКО в `Runtime.Config.host_functions`.
  Не предполагается интроспекция/модификация снаружи `zig/embed.zig`.

## Расширение `Runtime.Config`

```zig
pub const Config = struct {
    // ...существующие поля (global_search_roots, program_args, ...) без изменений...
    host_functions: []const HostFunctionEntry = &.{},
};
```

- Пример использования (полный, минимальный):

```zig
const panos = @import("panos_embed");

fn scale(x: f64) f64 {
    return x * 2.0;
}

var runtime = panos.Runtime.init(allocator, .{
    .host_functions = panos.hostFunctions(.{
        .scale = scale,
    }),
});
defer runtime.deinit();
```

```panos-cli
внешний "хост" функ scale(x: Число(64)) -> Число(64)

функ старт() -> Число
    scale(21.0) // 42.0
конец
```

- `game.rdynamic = true` в `build.zig` встраивающего приложения
  **больше не обязателен**, если ВСЕ host-функции идут через
  `host_functions` — он остаётся нужен, только если приложение ТАКЖЕ
  использует старый `pub export fn`-путь для каких-то функций (смешанное
  использование — допустимо, см. `spec.md`, User Story 4).

## Диагностика (не меняется по форме, меняется по одному новому классу
сообщений)

- Отсутствие символа — сообщение то же, что сегодня:
  `Resolve Error: библиотека 'хост' не экспортирует символ 'имя'`
  (срабатывает, если имя не найдено НИ в `host_functions`, НИ в образе
  процесса через `dlsym`).
- **Новое**: несовпадение сигнатуры между `.pns`-декларацией и
  зарегистрированной Zig-функцией — `Resolve Error` с явным указанием
  имени функции и характера несовпадения (число параметров или конкретный
  marshal kind), например:
  `Resolve Error: 'внешний "хост" функ scale' — несовпадение сигнатуры: объявлено 1 параметр, зарегистрировано 2`.
  Точный текст — на усмотрение реализации, обязательное свойство —
  диагностика с `span` декларации, не паника/`unreachable`.

## Не входит в контракт этой фичи (явно)

- Никаких изменений `.pns`-грамматики — `внешний "хост" функ ...`
  синтаксически идентичен дореформенному.
- Никаких изменений `Runtime.call`/`Runtime.load`/`Runtime.compile`
  (направление движок→скрипт не затронуто, см. переписку в
  `../jijka/ROADMAP.md`, "Зафиксированные решения").
- `docs/src/architecture/embedding.md` получает ДОПОЛНЕНИЕ (пример с
  `hostFunctions`), не правку существующего текста — вне обязательного
  скоупа `spec.md`, но естественный follow-up при реализации.
